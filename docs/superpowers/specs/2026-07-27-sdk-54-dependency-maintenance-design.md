# Expo SDK 54 Dependency Maintenance Design

Date: 2026-07-27

## Summary

Aurora will remain on Expo SDK 54, React Native 0.81, and React 19.1 for this
maintenance pass. Dependencies will be updated only where the resulting tree
remains compatible with Expo SDK 54 and the manually owned iOS project.

The work must not run `expo prebuild`, replace the committed Xcode workspace,
or claim native verification without a full Xcode installation. Existing
local changes to `expo-env.d.ts`, `tsconfig.json`, and
`docs/design-audit.md` belong to the repository owner and must remain intact.

## Current State

- Current app stack:
  - Expo `54.0.35`
  - React Native `0.81.5`
  - React `19.1.0`
  - Node engine `>=24 <25`
  - iOS deployment target `15.1`
- Expo's online SDK 54 compatibility check expects Expo `~54.0.36`.
- The current dependency tree passes type-checking and 47 Jest suites with
  240 tests after the Health-style feature branch was fast-forwarded into
  `codex/xcode-first-ios`.
- The authoritative native project is `ios/AURORA.xcworkspace`.
- Full Xcode is not installed or selected. CocoaPods regeneration and native
  Debug/Release verification are unavailable in this environment.

## Context7 Findings

Context7's current official Expo compatibility matrix identifies Expo SDK 55
as the next supported migration target:

- React Native `0.83`
- React `19.2.0`
- Node `20.19.x` or newer
- Xcode `26.2` or newer
- iOS `15.1` or newer

Official guidance recommends upgrading Expo SDK versions incrementally,
running Expo's dependency alignment command after changing the SDK, reviewing
each SDK's release notes, and using React Native Upgrade Helper for manually
managed native projects. Expo and React Native documentation both warn that a
manually owned native project must be migrated through reviewed native diffs;
Aurora must not regenerate it with `expo prebuild`.

The SDK 55 migration is intentionally deferred and documented in
`agents.md` as a future handoff.

## Maintenance Boundary

### Expo-governed packages

Run Expo's online compatibility checker first. Update Expo and Expo-owned
packages only to versions accepted by the SDK 54 compatibility map. The known
required update is:

- `expo`: `~54.0.35` to `~54.0.36`

Use Expo's alignment tooling to identify any additional SDK-managed mismatch.
Do not install the npm-registry "latest" major for Expo packages because those
versions belong to later SDK lines.

### JavaScript-only and tooling packages

JavaScript-only packages and development tools may move to the newest
compatible release within their current major version. Candidate groups
include:

- React Navigation 7 packages
- ESLint 9 and matching TypeScript ESLint 8 packages
- Prettier 3
- TypeScript 5.9
- `ts-jest` 29
- Babel module resolver 5
- Expo 54 Babel/Jest presets

Each group must be installed and verified independently enough to identify
the source of a regression. Major-version upgrades such as ESLint 10, Jest
30, TypeScript 7, date-fns 4, or Zustand 5 are outside this maintenance pass.

### Native modules

Do not update a native module merely because npm reports a newer version.
Native modules include, but are not limited to:

- React Native itself
- datetime picker
- gesture handler
- MMKV
- Reanimated
- safe-area context
- screens
- SVG
- worklets
- HealthKit integration

A native package may change only when Expo SDK 54's compatibility checker
requires it. Any such change must be recorded as requiring a future
`npm run ios:bootstrap` and native Debug/Release builds on a Mac with stable
Xcode. No Podfile.lock entry may be fabricated or hand-edited.

## Security Advisory Policy

The production audit currently reports transitive advisories, including
issues under Expo CLI/Metro, React Native tooling, and the config-plugin
dependency tree used by `react-native-health`.

For each material advisory:

1. Trace the dependency with `npm explain`.
2. Prefer a compatible upstream patch selected by Expo SDK 54.
3. Use an npm override only when the patched transitive version satisfies the
   parent package's declared range and all verification gates pass.
4. Do not use `npm audit fix --force`.
5. Do not downgrade `react-native-health` solely because npm proposes an older
   package as an audit fix.
6. Record advisories that cannot be removed without an SDK or native-module
   major upgrade in the final handoff.

Audit counts are evidence for investigation, not proof that every advisory is
reachable in the shipped iOS application.

## Files and Ownership

Expected maintenance changes:

- `package.json`
- `package-lock.json`
- `agents.md`
- this specification and the implementation plan

Native files change only if the Expo SDK 54 compatibility map requires a
native package update and the change can be generated by the owned bootstrap
workflow. User-owned dirty files must not be staged, rewritten, or discarded.

The existing Expo Metro process may be restarted after dependency changes so
the final preview uses the updated dependency tree.

## Verification

All npm commands use:

```text
/opt/homebrew/opt/node@24/bin/node /opt/homebrew/opt/node@24/lib/node_modules/npm/bin/npm-cli.js
```

Required gates:

1. Online Expo SDK 54 dependency check reports no mismatch.
2. Expo Doctor reports no new actionable project issue.
3. `npm ls --depth=0` exits cleanly.
4. TypeScript type-check passes.
5. ESLint passes.
6. All Jest projects pass.
7. iOS Expo export succeeds.
8. Website type-check and production build pass.
9. `git diff --check` passes for the maintenance diff.
10. Metro serves an iOS bundle successfully after restart.
11. Production and full audit results are captured and unresolved advisories
    are explained rather than hidden.

Native bootstrap and unsigned Debug/Release builds must be attempted only when
stable full Xcode is installed and selected. Until then, report the exact
environment limitation.

## SDK 55 Handoff

The future SDK 55 owner must:

1. Install and select stable Xcode 26.2 or newer.
2. Preserve the manually owned `ios/AURORA.xcworkspace`.
3. Upgrade Expo one SDK at a time and align Expo packages using the official
   compatibility command.
4. Move React Native to 0.83 and React to 19.2 as a coupled change.
5. Review React Native Upgrade Helper and Expo SDK 55 release-note native
   diffs before editing the Xcode project, Podfile, plists, entitlements,
   AppDelegate, assets, or shared scheme.
6. Never run `expo prebuild`.
7. Run the owned `npm run ios:bootstrap` workflow.
8. Pass JavaScript checks, iOS Expo export, unsigned Debug and Release
   simulator builds, and physical iPhone/iPad smoke tests.
9. Verify Expo Go fallback behavior and real-device read-only HealthKit
   behavior separately.

## Acceptance

The maintenance pass is complete when the SDK 54 tree is online-validated,
all available automated gates pass, Metro serves the updated app, unresolved
audit findings are documented, and the SDK 55 handoff is present in
`agents.md`. No dependency major or native migration may be implied by a
passing JavaScript test suite alone.
